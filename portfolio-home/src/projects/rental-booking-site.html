A production booking-enquiry site for a short-term rental owner, built to win direct bookings without platform commission. I took it from a static design handoff to a live site with a spam-protected enquiry pipeline. The client's name is withheld at their request.

Key decision
Hold back search indexing until the real domain is live.
Why
During client review the site lived on a placeholder subdomain. If search engines had indexed it, the future production site would have competed with its own duplicate. Zero-risk SEO went in immediately, and indexing waited for the domain switch.
Also
I sized the infrastructure to the job: four static pages and one serverless function, with no database or separate CI service.

How it's built

Four static pages and one serverless function, hosted, secured and deployed on Cloudflare. Email goes out through Resend.

PieceWhat it does
Booking widgetThe only interactive part of the site. The chosen dates and guest count carry over to the enquiry form through the browser's local storage and the link, so the form arrives prefilled.
WorkerOne entry point. Form posts go to the enquiry handler; everything else is served as a static page.
Static pagesBuilt by Astro, with no JavaScript except the booking widget.
/api/enquireValidates the form, verifies the spam token, then emails the owner. If email isn't configured, it fails loudly instead of dropping the enquiry.
TurnstileBlocks spam without making real guests solve a puzzle.
ResendSends the enquiry email, with reply-to set to the guest so the owner can just hit reply.
Workers BuildsRuns the Astro build and deploys on every push. No separate CI service.
